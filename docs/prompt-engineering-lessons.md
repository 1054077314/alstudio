# 写提示词的核心方法论（来自一次聊天整理）

> 适用：Claude Opus 5 / 新一代模型（GPT-5 级别同理）。核心结论：**从“提示词工程”转向“上下文工程”**。

## 一、核心结论

模型变强后，大部分手写提示词是废话。原则只有两条：

1. **能删的删**：别教它“怎么做”——它自己会（验证、自检、把活干完）。
2. **该留的留**：只留两类——**红线**（不许干的事）和**验收标准**（做成什么样算好）。

人的角色从“写一句漂亮的 prompt”变成“把工作环境收拾利索，把‘什么叫干好了’讲清楚”。

## 二、上下文分层（决定信息放哪）

| 层 | 放什么 | 备注 |
|---|---|---|
| System Prompt | 产品环境、基本任务 | 自建 agent 才需设计 |
| CLAUDE.md | 轻量；只写看代码库看不出来的“坑” | 别抄目录结构 |
| Skills | 团队/产品专属的观点、方法论 | 长了拆文件，按需加载 |
| References | @ 引用的规格、原型、测试、代码 | **代码/HTML 优于文字描述** |

六条转变（Opus 5 实测）：死规则→判断力；示例→接口设计；全量前置→按需加载；重复指令→单一来源；手动记忆→自动记忆；文字规格→代码/测试/Rubric。

## 三、万能模板

```
背景：<事实 + 数字 + 不能变的条件>
任务：<我要你干什么，一句话>
要求：<格式 + 不干什么>
```

- **通用/知识类问题**：删掉“背景”直接问。
- **具体/算账/代码/规划类问题**：把“背景”写实（数字、边界）。

判断标准：换了人问同一问题、AI 该给不同答案 → 才需要补事实。

## 四、按场景模板

- **问问题/调研**：`先读 xxx 再回答；给文件路径和行号，不确定明说；不要改任何代码。`
- **修 bug**：`复现/期望/实际；先给根因一句话，我确认后再改；只改导致 bug 处。`
- **加功能**：`参考 yy 的实现加 xx；验收=pytest 全绿；不加新依赖、不动无关文件。`
- **代码审查**：`只看本 PR 改动，全列出别自行筛选；别改代码。`（写“只报严重的”它真会少报）
- **重构**：`行为不能变，改完跑全量测试证明；小步提交可回滚。`
- **长任务**：`先列计划我批准再动；没把握的决定停下来问，别猜。`

通用三条：给参照物 > 给描述；给验收标准（测试/原型）> 给形容词；每条规则只写一遍。

## 五、反面教材（旧式写法，删掉）

- `你是一位顶级 XXX 专家` —— 人设没用，且与任务无关时纯噪声
- `请先分析核心，再一步步给出步骤` —— 模型本就如此，强制只产出凑数内容
- `控制在合理字数` —— 模糊=没约束，要么写死要么删
- `输出到 xxx.md，不要读其他文件` —— 聊天场景用不上，仅 agent 工具需要

## 六、实例：一个“具体问题”的提示词怎么写

原始（啰嗦）：一堆人设 + 步骤仪式 + 空括号 + 模糊字数 + md 输出指令。
精简后（可直接发）：

```
背景：乌鲁木齐，现金200元，9月10日发薪4000元，工作不稳定；目前无住处，
需撑18天，只能通过正规网贷周转。青旅48元/天；合租押一付一，价位按当地行情估。

请在500字内：
1. 判断住青旅还是合租；
2. 计算资金缺口，给出借款金额和分期方案；
3. 安排发薪后4000元的用途。

要求：先结论后理由
```

要点：数字全、问题编号、字数封顶、结论先行。删掉的四句废话对人设/步骤/模糊字数/md输出不影响答案。

### 该例的回答骨架（演示“先结论后理由”）

1. **住青旅**：18天成本≈864，当天入住无合同；合租押一付一一次性≈1200+且需找房签合同，工作未定不灵活。
2. **缺口≈1500**：必需 864(住)+720(吃行)≈1584，手头200 → 借1500、只借一笔、3期以内。渠道：雇主预支>持牌机构(借呗/微粒贷/京东金条)；**不碰**无牌App、砍头息、714高炮、以贷养贷。
3. **发薪日分配**：还借款本息≈1550 → 续住≈700 → 吃饭≈800 → 应急储备≈600 → 机动≈350。第一件事还清借款。

> 为什么“只借一次”：利息叠加、还款日错开易逾期、以贷养贷滚雪球、征信变花。能发薪就还，闭环结束。
> 利息参考：持牌按日万2~万5(年化7.2%~18.25%)，1500用18天利息约8~14元；看清展示的年化利率，>24%换一家。
