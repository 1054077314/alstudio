# 提示词指南（alstudio）

> 一份从实战里磨出来的提示词写法笔记。核心一句话：**把关键决策变量显式写出来 + 控制输出格式 = 答案质量可控**。

## 一、核心心法（为什么这么写）

**1. 起点：清理一个真实提示词**
原始提示词（乌鲁木齐生存规划）塞了人设、过程描述、输出路径等废话，还留了空白变量。
清理后保留的是影响结论的数字（现金200、9/10发薪4000、青旅48/天、合租600-800/月押一付一）、
不确定项（工作不稳定）、明确输出约束（500字内、先结论后理由）。

**2. 提示词质量取决于什么**
取决于"改变结论的变量"是否显式在场——在提示词里，或在上下文里，二者居其一即可。
验证：把清理版压成极简版（丢了关键变量），靠上下文记忆第二次回答才和第一次一样；
冷启动（新会话单独跑）时极简版会给出相反/更差的答案。结论：**删废话永远安全，删变量必翻车**。

**3. 模板不是万能的**
模板管骨架（结构、约束、该问的维度），事实管血肉（改变结论的变量只能来自自身盘点）。
模板越工整，变量缺失时答案反而越可信、错得越隐蔽。

**4. 读 Anthropic 官方博客后的体系**
演化线：怎么措辞 → 怎么策划信息(上下文工程) → 为更强模型做减法(删80%系统提示)。
- 上下文是稀缺资源，token 越多模型越容易"记漏"(context rot)。
- 指导原则：用最小的高信号 token 集合达成目标。
- 系统提示词停在"正确高度"：别硬写 if-else，也别空洞。
- Claude 5 代 6 条新规则：规则→判断力 / 示例→设计接口 / 全前置→渐进披露 /
  重复强调→工具描述写一次 / 手动记忆→自动记忆 / 简单规格→富引用(代码>截图>文字)

**5. 一句话心法**
写好提示词 = 把关键信息显式说出来 + 控制输出质量 = 策划最小高信号 token 集合。
不满意就补信息重问，不要换花样重问。

## 二、万能模板（任何场景先套这个）

背景：（我是谁，现在什么情况，相关数字和事实全列出来）
任务：（要你干什么，一句话）
要求：
- 输出格式（多少字 / 分几条 / 先结论后理由）
- 有不确定的直接说不知道，别编

## 三、按场景模板

### 1. 做选择（租房、买什么、选方案）
背景：我的情况和数字（钱、时间、限制条件、我不确定的地方）
选项：A是… B是…（价格/代价写清楚）
任务：帮我选一个，算清楚账
要求：X字内，先说选哪个再给理由

### 2. 写东西（文案、邮件、报告）
背景：写给谁看的，他们关心什么，用来干什么
任务：写一篇（主题），要点是（1、2、3）
要求：X字左右，语言风格（口语/正式）；不要空话套话，每个观点带具体例子

### 3. 改代码 / 技术问题
背景：环境是什么（语言、框架、版本），报错信息原文贴上来
任务：（直接说"修改"或"解释"，别说"帮我看看"）
要求：只改和问题相关的部分，别顺手重构；改完说明每处改动的原因

### 4. 学东西 / 让它解释
背景：我已知的水平（零基础 / 懂X但不懂Y）
任务：解释（概念），用（生活类比 + 一个具体例子）
要求：不超过X字，别堆术语，最后给一个我能动手验证的小练习

### 5. 检查 / 找茬
背景：（材料粘贴进来）这是我写的（东西）
任务：按这几个标准挑毛病：（标准1、标准2、标准3）
要求：每条问题指出位置+原因+怎么改，没问题的方面不用夸

## 四、发出前 6 秒检查

1. 影响结论的数字都写了吗（价格、日期、期限、不确定项）
2. 要什么样的答案说了吗（字数、条数、格式）
3. 两句话有没有打架（又要详细又要50字）
4. 加了"不知道就说不知道"吗
5. 动词明确吗（"改成X"而不是"建议一下X"）
6. 每个句子都改变结论吗？不改就删

不满意就**补信息重问**，不要换花样重问。
